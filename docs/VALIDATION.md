# 两阶段版本验证（2026-10-28）

当前交付由两个通用 Skill、版本化规范规则库和逐零件匹配组成。实际模型执行通过 Pi 非交互入口，全部请求与成功响应的模型标识为 `deepseek-flash`。GPT负责独立读源、参考集和开发核对，没有作为产品运行时的隐藏回退模型。

## 实际资料验证

- 2份规范、8份单页图纸通过本机 HTTP 上传与任务接口执行；最终2个规范库和8个零件任务完成。规范共28个物理页，每个物理页保留并提交；逐图使用整页和真正高分辨率局部图。
- 规范库按原件、解析 Skill 哈希和流程版本缓存，最终两库各进行2批提取、5批逐页查漏，共14次实际模型调用。客户材料、规则值、图号和参考答案不写入公共 Skill。
- 矢量表格提取实际格线、单元格边界和合并范围，交给模型和原图共同核对；扫描图仍由 Flash 看图。一个重点合并表额外按全部16个分档、64个核心数字逐格核对通过，这不是所有表格均无遗漏的证明。
- 独立参考在比较前冻结：55项规范事实、71项图纸事实，原文件哈希与证据裁图均在本地报告。规范55项中53一致、2部分；图纸仍存在部分缺失和冲突，不能声称与GPT完全一致。参考自身发现的图形圈号误读有独立勘误，不覆盖原冻结文件。
- 先用2张代表图迭代，再保留6张作为后续验证；验证发现问题后的确定性约束和来源复核单独记录，不能把这些图继续当作未知测试。部分重试复用正常结束的初始候选，保留初始匹配与新审计各自的Skill哈希，没有宣称所有图用最终Skill重新冷跑。
- 实测曾出现输出达到长度上限和来源文件名缩写；系统明确判失败。改为增量审计补丁、固定来源代号后逐零件重试，其他已完成零件保留。
